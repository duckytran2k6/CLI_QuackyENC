# **Internals**

This document provides an overview of QuackyENC's internal design. It contains the details on things such as the cryptography algorithms
in use, how I/O is managed, and different layers of processing within the tool. The goal is to give a clear understanding on both high-level
user-interaction logic and the low-level cryptography operations that help ensure the security and compatability for the tool.

# **Core Cryptography**

QuackyENC uses the following algorithms:
* **AES-GCM:** Stands for _Advanced Encryption Standard_ (AES) which is a symmetric-key encryption algorithm with the _Galois/Counter
Mode_ (GCM) for higher efficiency since the algorithm does not require data padding. 

* **RSA:** Stands for _Rivest-Shamir-Adleman_, which is a different algorithm from AES by having a pair of keys. Used to perform cryptography
operations on the Secret Key generated by the AES. This algorithm does not require a mode like AES, but it requires a padding scheme as 
a crucial for its security. The ECB mode is only played as a dummy holder in order to fit with Java's crypto libraries format.

* **OAEPWithSHA-256AndMGF1Padding:** OAEP stands for _Optimal Asymmetric Encryption_, the newest padding scheme designed to overcome PKCS1's
weakness. By combining with SHA-256 for internal has and _Mask Generation Function 1(MGF1)_ to mix randomness, this will help with producing
different ciphertext every new session even for the same data.

* **PBKDF2WithHmacSHA256:** Stands for _Password-Based Key Derivation Function 2_, this function is used to get the secret key by deriving it
from the user's password + salt and uses the HmacSHA256 to hash internally, in this case 65,536 iterations, then outputs a 256-bytes secret key.

# **Different Methods**
QuackyENC provides the user with 2 encryption method: password-based and key pair-based. Both of the methods use AES-GCM but the way their
authentications work a bit different from each other. In common, both methods will use a Secret Key and an IV as the final authentication
layer before gaining the access to the encrypted main data. An Initialization Vector (IV) is a random sequence 12-bytes which is referred as
a nonce for each encryption operation, ensures that in case of the same data is being encrypted with the same secret key will produce different
ciphertexts each time.

## _ **Password-based method**_
This is the more simple method as you only need to come up with a password that you will share it along with the other auth info files included
in the zip folder. The way this works is that the user enter a valid password, then upload all the text files they want to be encrypted. Then, 
those encrypted text files, a salt file, and an IV file. A salt is a random 16-bytes generated which will be added to the password before
hashing. The RSA algorithm will turn the plain-text password into a strong cryptographic key and derive it as explained above. Once the user
get the key, combining it with the IV, the program will use it to decrypt the main encrypted data.

## **Key Pair-based method**
For this method, it is a bit more complicated as it requires an initial step from the receiver. The receiver will need to use the key pair 
generator to get a pair of public and private keys. Then, the receiver will send the public key file to the sender which will be used to 
encrypt the data. Once the sender uploaded the text files with the public key file, the tool generates a 256-bytes AES secret key and encrypts
it using the RSA algorithm. Afterward, the sender will receive a zip folder contains the encrypted text files, an IV file, and an encrypted 
secret key file. Once this is sent to the receiver, they will decrypt it using their own private key. The tool will check if the keys are in 
pair then first decrypt the secret key. Finally, the decryption process is the same for the other method. The main goal for this method is to 
a better security layer for handling the secret key by having a key pair instead of a normal password.

# **Conclusion**
The main goal of QuackyENC is to understand on how different methods are using different algorithms to enhance the security in many ways by 
going through how each works internally. While most of these algorithms are mainly about improving the security by adding more randomness 
into each layer, it still works in a certain logical way so it maintains that "randomness" factor so that attack methods such as Brute-Force 
and Adaptive Chosen-ciphertext like Bleichenbacher's attack can not break through these layers easily. Moreover, the tool is updated with an 
automatic clean up service that will make sure to clean up all the temporary files as well as the old authentication tags after every decryption
attempt so that there will be less chance of the data being re-used for leaking purpose. Combining that with the tool being able to run locally 
offline will significantly reduce the chances for the attackers to break into the tool.
